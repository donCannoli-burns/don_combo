## Found issues / dispositions

1. **High — Mixed observation certainty.** Whale sightings, whale actions and item deltas were aggregated in a single Pool 1 total. A whale seen and then combed can count twice in that total. Pool 2 cursed pirate gear may generate three item deltas on one comb, which are **one category reward event** for cooldown statistics. **Patch:** the new timing reader uses action/item-delta events only and collapses same-comb same-kind pirate equipment; original counts and all sightings are retained separately. UI must not represent raw Pool 1 counts as like-for-like rare-drop probability.
2. **High — Wrong rare-item attribution to tile recovery.** Previous native `captureTileRecovery` accepted the first positive item not on a partial 'common' denylist; ordinary beach items omitted from that list could set `last_harvest_epoch` and distort cooldown/revisit features. **Patch:** only positively recognized Pool 1/Pool 2 rare-item names can create a new inferred rare harvest, with all other deltas still retained in the event log. **Residual:** existing saved recovery entries produced under the old rule are _not automatically declared clean_ or deleted. Audit/quarantine legacy entries before trusting historical revisit estimates.
3. **High — Inadequate time scale for gausie's hypothesis.** Original `14_plus_days` bin conflated 15 days and ~two years; analysis only considered repeat attempts on one exact tile. **Patch:** added 14–30, 30–90, 90–180, 180–365, 365–730, 730+ day bins and independent **three conceptual timing lanes for EACH pool**. Also observe category reward-to-reward gaps when the coordinates change. No model-based cooldown or causal transfer inferred.
4. **Medium — Timestamp conflation.** The timestamp on an event was created after action, but its beach layout was observed before WaterSheep inference; a visit near a UTC date boundary could place scratch evidence in the wrong day. **Patch:** add `pre_action_observed_at` at layout read; retain `observed_at` as the post-action record date, use pre-action date for daily scratch history, preserve older event fallback.
5. **High — Action confirmation is incomplete.** For regular Combo and some fallbacks, CLI execution does not have a separate, persisted, post-action success receipt before `recordBeachObservation`. A WaterSheep paid/free run checks counters _after_ the event is appended; a failed check means a failed-run event can be mistaken for verified success. **Not closed by this audit patch.** Recommended fix: bind post-action execution/turn-counter receipt to event identity, and keep `attempted` versus `verified` cohorts separate with readback/reconciliation.
6. **Medium — Multi-file writes are not a transaction.** The aggregate is written before the append-only event; a crash between writes can cause drift, and optional index writers intentionally catch exceptions. **Not closed**. Add drift detection comparing event IDs + the aggregate and rebuild non-authoritative indexes from JSONL; make event append the authoritative commit with explicit recovery checkpoints.
7. **Medium — Incomplete historical corpus.** Local ML JSONL is authoritative for this project's recorded events, but historical KoLmafia session logs predating instrumentation are not imported. A past `raretiles.json` coordinate without an observed date is not a cooldown observation; Veracity's separately mined 2019+ logs are external research, not automatic evidence in this model. **Not closed.** A future import needs typed evidence, source provenance, timestamp validity, duplicate control, and user consent for any private historical logs.
8. **Medium — Player provenance gap in older unbound events.** The run-bound events are filtered by player ID; unbound legacy events lack a reliable player ID and currently contribute to baseline regardless of provenance. **Not closed**; show as unbound cohort and avoid treating them as individually attributable when fitting a personal cooldown.
9. **Low — 500-event snapshot tail.** Exported runtime contains the most recent 500 ML events, not all 3,129 raw records, although the native historical replay reads all JSONL. A snapshot alone cannot externally verify the full historical corpus. **Not closed**; export a separate, hash/size-bound evidence manifest or opt-in JSONL archive.
10. **Medium — Shared global chance vs. transferred timer unresolved.** Repeated reward observations at different coordinates are recorded, but sparse observations and unknown other-player actions mean they do not distinguish moving opportunity from a shared global category cooldown. **Not closed**; compare hypotheses explicitly after sufficient independent dated data.

## Three proposed peaks: design contract

Per Pool 1 and Pool 2, define **short** (`common_rare`), **middle** (`uncommon_rare`), and **long** (`rare_rare`) _candidate lanes_. Each lane retains category reward-event count, observed inter-reward category gaps, same-versus-cross-coordinate counts, median observed interval (if any), a multi-scale modal bin, and data sufficiency status. No lane is called a confirmed `cooldown peak` solely from a sample median. Gausie's ~two-year rainbow-pearl estimate motivates the long-axis bin, **not a fixed parameter**. The model receives only a compact derived summary, not a duplicated multi-thousand-event JSON payload.

The old observed attempt-gap curve remains available as a distinct measure. Category chronology is a separate measure: `twinkle_fallback` driftwood still counts as a recorded driftwood reward but not a canonical exact-known-rare attempt.
